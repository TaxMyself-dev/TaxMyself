# התאמת מחקר SHAAM הקודם לממצאים הנוכחיים

מסמך הבסיס הוא [SHAAM integration audit](../../research/shaam-integration-audit.md)
מ-2026-09-06. הבדיקה הנוכחית לא ביצעה קריאות חיות ולא שינתה את היישום.

## עדיין תקף

- מסקנת **NO-GO לייצור אוטומטי** נשארת בתוקף.
- פערי auth/token/state, tenant authorization, רישום סודות/PII, חוזה API,
  mapping סוגי מסמך, idempotency, sandbox/certification ו-test coverage
  נשארים חסמי P0/P1 עד ראיה נגדית בבדיקה ובאישור.
- הדרישה להשאיר טוקנים בצד השרת, לקשור הרשאה לעסק/actor, לאמת callback
  ו-state, ולמנוע fallback שקט נשארת תקפה.
- אין ראיה לחיבור production מאושר; סביבת sandbox אינה אישור ייצור.

## עודכן או הוחלף

- **סף 2026:** טבלה ישנה במפרט חשבוניות ישראל 2.0 אינה המקור הקובע.
  חוק המע״מ המאוחד המעודכן מצביע על 10,000 ₪ לפני מע״מ בין 1.1–31.5.2026
  ועל 5,000 ₪ מ-1.6.2026; דף השירות הנוכחי מציג מעל 5,000 ₪. כל תיאור אחר
  במחקר קודם מוחלף בכך, בכפוף לאימות מומחה של תחולה/חריגים.
- **נספח אבטחה:** העותק הרשמי שנשמר מתוארך 22.7.2025, לא 2026. הדרישות
  עצמן — 72 שעות, PT, 2FA, הצפנת סודות ולוגים ל-12 חודשים — נשארות, אך
  metadata קודמת שייחסה לו שנת 2026 מתוקנת.
- **קובץ אחיד:** נוספה תוספת רשמית מהדורה 1.0/3.2026 המחייבת, כתנאי
  רישום, שידור מידי אחרי הפקה. היא לא הייתה חלק מרכזי ב-audit הקודם.

## דורש אימות מחדש

- URLs, versions, scopes, payload enums, error codes וסביבת production של
  Open API סמוך ל-onboarding; מדריך ישן או code comments אינם מקור קובע.
- האם endpoint ייצור של API הקובץ האחיד הופעל מאז פרסום S05; המסמך השמור
  אומר Sandbox בלבד והודעה עתידית.
- סטטוס רישום התוכנה, הרשאות דיגיטליות וחתימת נספח האבטחה בפועל.
- האם מיפוי document type ו-`invoice_reference_number` הנוכחי תואם את
  החוזה הפעיל ואת כל סוגי המסמך של Keepintax.
- מספר לקוחות SHAAM בפועל לצורך ספי PT; המחקר לא ניגש לנתוני production.

## ראיות סגירה נדרשות

כל finding נסגר רק עם commit/test, תוצאת sandbox רשמית, מסמך onboarding או
אישור מקצועי מתאים. שינוי טקסט בתיעוד או הצלחת happy path אינם סוגרים פער.
