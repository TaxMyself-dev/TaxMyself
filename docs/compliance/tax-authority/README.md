# מפת ציות לרשות המסים — מסמכים והנהלת חשבונות

עודכן לאחרונה: 2026-09-11. מסמך זה הוא מפת ראיות הנדסית, לא חוות דעת
משפטית או חשבונאית. לפני החלטת מוצר, עליה לייצור או שינוי טיפול חשבונאי יש
לקבל אישור מרואה חשבון/יועץ מס, ובסוגיה משפטית — מעורך דין ישראלי מתאים.

## מה מכוסה

- תיעוד פנים וחוץ, מסמכי מכירה, חשבונית מס, קבלה, הודעת זיכוי ומסמך ממוחשב.
- מספור, תיקון, ביטול, זיכוי, שמירת מקור, גיבוי ויכולת ביקורת.
- חשבוניות ישראל ומספרי הקצאה, SHAAM Open API והרשאות דיגיטליות.
- דיווח מע״מ מפורט/PCN874 וקובץ במבנה אחיד, לרבות תוספת API ממרץ 2026.
- אבטחה, הרשאות, לוגים, שמירת אסמכתאות ובדיקות קבלה/רישום תוכנה.

הממצאים המפורטים נמצאים ב-[מטריצת הדרישות](requirements-matrix.md), סדר
הטיפול ב-[פערים ומפת הדרך](gaps-and-roadmap.md), ותכנית האימות
ב-[בדיקות ורישום](testing-and-certification.md). פרטי המקורות והעותקים
השמורים נמצאים ב-[אינדקס המקורות](source-index.md).

## היררכיית סמכות ותיוג ראיות

1. חוק ותקנות שפורסמו כדין.
2. הוראות ניהול פנקסי חשבונות מכוח הדין.
3. מפרט טכני/נוהל/נספח אבטחה רשמי של רשות המסים.
4. דף שירות רשמי והודעות תפעוליות.
5. פרשנות צוות המחקר — לעולם אינה מוצגת כחובה משפטית.

במטריצה כל שורה מתויגת: **חובה משפטית**, **הנחיה טכנית**, **המלצה
הנדסית**, **פרשנות**, או **שאלה פתוחה**. `קיים`, `חלקי`, `חסר` ו-`לא
נבדק` מתארים רק את הראיות שנמצאו בקוד ובמסמכים; הם אינם אישור ציות.

## גבולות ומגבלות

- נוסח רשמי מאוחד ונגיש של הוראות מס הכנסה (ניהול פנקסי חשבונות),
  התשל״ג-1973 לא אותר באתר ממשלתי במהלך הבדיקה. לכן דרישות שמקורן בהוראות
  עצמן נשענות על חוזרי רשות המסים, התקנות המאמצות אותן ומפרטים רשמיים,
  ומסומנות לאימות מקצועי מול הנוסח המעודכן ברשומות.
- מפרט טכני ישן אינו גובר על חוק/תיקון חדש. בפרט, טבלת הספים במפרט
  “חשבוניות ישראל” מהדורה 2.0 אינה מקור הסף העדכני ל-2026.
- לא נעשתה בדיקה מול ייצור, בסיס נתונים, לקוחות אמת, מזהים אמיתיים או
  שירות SHAAM חי. לא הוגשה בקשת רישום ולא התקבל אישור מרשות המסים.
- מסמך זה אינו מכריע אם Keepintax עצמה “תוכנה החייבת ברישום”; זו שאלה
  משפטית/עובדתית המחייבת אימות מקצועי.

## תחזוקה

- בעל תפקיד ציות בודק אחת לרבעון ובטרם שחרור מסמכים/דיווחים: דפי שירות,
  גרסאות מפרט, שינויי חקיקה, ספים ותאריכי תחולה.
- כל מקור חדש נרשם עם URL, תאריך גישה, גרסה/תאריך, SHA-256 אם נשמר, וסיבת
  החלפה. אין להחליף PDF קיים בשקט.
- שינוי חובה יוצר משימת עבודה נפרדת; המטריצה מתעדכנת רק עם ראיית קוד,
  בדיקה או אישור רשמי. ראיה חסרה נשארת `לא נבדק`/`חסר`.
- בדיקת הספים של חשבוניות ישראל והפעלת API הקובץ האחיד חייבות להיעשות גם
  סמוך לעלייה לייצור, משום שהמסמכים הרשמיים כוללים הוראות מעבר תפעוליות.

## מסקנה נוכחית

אין בסיס להצהיר שהמוצר תואם. קיימים מנגנוני מספור, מסמכים, יומן, דוחות
והפקת קובץ אחיד, אך נמצאו פערים קריטיים סביב מחיקה/החזרת מונים של מסמך
שהופק, מסמך ממוחשב וחתימה, סודיות ולוגים, בידוד דיירים, והיעדר ראיית
רישום/סימולטור/שידור API. חיבור SHAAM האוטומטי נשאר **NO-GO לייצור** עד
סגירת שערי האבטחה, החוזה, ההרשאות והקבלה המפורטים במסמכים אלה.
