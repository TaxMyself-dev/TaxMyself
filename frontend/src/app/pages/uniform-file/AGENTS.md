## Purpose
Generates the "מבנה קבצים אחיד" export for a selected business and period,
downloads it as a ZIP, and offers a separate explicit server-side SHAAM
submission flow.

## Key entities/files
- `uniform-file.page.ts` — `UniformFilePage`. Filter form (business + date-range only, via `app-filter-tab`), calls `FilesService.createUniformFile`, renders document/list summary tables, base64→zip download.
- `uniform-file.page.html` / `.scss` — filter tab, summary tables (`uniformFileDocumentSummaryTitles`, `uniformFileListSummaryTitles`), report-details header.
- `uniform-file.module.ts` / `-routing.module.ts` — Angular module wiring; imports `GenericTableComponent`, `FilterTabComponent`.
- No dedicated `.service.ts` in this directory — the actual file-generation HTTP call lives in the shared `FilesService` (`createUniformFile`), not a page-local service.
- `ShaamService` provides typed prepare/connection/transfer/poll calls. Tokens,
  generated bytes and signed upload URLs never enter this page.

## Main flows
- Select business + date range (date-range period mode only) → `onSubmit` resolves dates via `DateService.getStartAndEndDates`, normalizes them to ISO `YYYY-MM-DD` for the API and stable summary display, then calls `createUniformFile(startDate, endDate, businessNumber)`.
- `createUniformFile` calls `FilesService.createUniformFile`, formats the returned `document_summary`/`list_summary` rows (comma-formatted sums), and triggers `downloadBase64Zip` which decodes the base64 zip payload and auto-downloads `openformat.zip`.
- Errors during generation surface as a toast via `MessageService`.
- After ZIP generation, the user explicitly prepares a persisted submission,
  connects the uniform-file Daily Token when necessary, explicitly transfers,
  and manually polls. `PROCESSING` is labelled as waiting and never as approval.
- Connection checks show active connections as success and missing connections
  as informational prompts; absence of authorization is never presented as a
  completed/successful operation.
- Re-selecting a period clears the page's previous submission state; the backend
  remains the source of truth and idempotently reuses the same artifact.
- Immediately before redirecting to SHAAM OAuth, the page stores only a safe
  session-scoped resume context (business, period, internal submission ID and
  display metadata). On return it reloads the submission through the
  authenticated business-scoped backend endpoint, verifies the business and
  period match, refreshes connection status and restores the submission card.
  Tokens, generated bytes and signed URLs are never stored in browser storage.
- A persisted `RETRYABLE_FAILURE` is historical submission state, not current
  connection state. Once the Daily Token connection is active, the UI presents
  it as ready for another attempt and hides the stale prior error; while
  disconnected it asks for reconnection and explains the prior failure in Hebrew.
